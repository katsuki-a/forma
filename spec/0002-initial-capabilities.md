# 初期の機能範囲

初期版が満たす機能の契約。基礎操作は [プロダクトの核](0001-product-core.md) を参照する。以下は未実装。各機能の未確定な詳細を推測して拡張しない。

## FRM-010: アプリの作成と視覚的な編集

空の定義、テンプレート、既存アプリの定義の複製を起点としてアプリを作成し、データ項目をドラッグ＆ドロップで配置できる。

根拠: INT-004

確認条件: 三つの起点それぞれからアプリを作成でき、視覚的な操作で項目の配置を変えられる。複製先の定義変更で元のアプリの定義が変わらない。

## FRM-011: 定義変更の動作確認と反映

編集したアプリ定義を、利用中のアプリへ反映する前に動作確認できる。

根拠: INT-004

確認条件: 変更した定義を試している間は利用中の定義が維持され、反映操作後に変更が利用者へ適用される。

## FRM-012: アプリの識別と外観

アプリごとに名前、説明、アイコン、テーマを設定できる。外観は [デザインの契約](0003-design-system.md) に従う。

根拠: INT-004, INT-003

確認条件: 設定した名前・説明・アイコン・テーマが対象アプリに反映される。テーマを変えても共通部品の操作や状態の意味が変わらない。

## FRM-013: 入力項目の種類

一行テキスト、複数行テキスト、数値、単一選択（ラジオボタン・ドロップダウン）、複数選択（チェックボックス・複数選択欄）、日付・時刻・日時、リンク（URL・電話番号・メールアドレス）、ユーザー・組織・グループ選択を定義できる。

根拠: INT-004

確認条件: 列挙した各型の項目を作成し、その型に沿った値を入力・保存・参照できる。参照先の管理機能や入力ルールの追加範囲は別途決める。

## FRM-014: 計算項目

アプリのデータを用いた計算式を項目に設定し、結果を表示できる。

根拠: INT-004

確認条件: 定義した式が参照する値を変更すると結果が反映される。利用可能な演算・関数とエラー時の扱いは、実装前に詳細を定義する。

## FRM-015: システム項目と値の重複禁止

レコード番号、作成者・更新者、作成日時・更新日時を保持する。対象となる項目に値の重複禁止を設定できる。

根拠: INT-004

確認条件: 作成・更新の操作に応じてシステム項目が反映され、重複禁止を設定した項目に既存の値を重複して保存できない。対象の型と空値の扱いは実装前に定義する。

## FRM-016: レコードの変更・削除・再利用

既存レコードを編集・削除し、その内容を元に新しいレコードを作成できる。複数レコードをまとめて削除できる。

根拠: INT-004

確認条件: 編集内容が対象レコードに反映され、指定した複数件を削除できる。再利用して作成したレコードは元のレコードとは独立して変更できる。

## FRM-017: 状態と担当者

アプリに処理の状態と遷移を定義し、各段階の担当者を指定できる。

根拠: INT-004

確認条件: 設定した遷移によってレコードの状態を変更し、現在の段階と担当者を参照できる。条件付きアクションや高度な承認フローの採用は含まない。

## FRM-018: 情報共有の入口

アプリへの入口とお知らせをまとめたポータルを持つ。

根拠: INT-004

確認条件: ポータルから利用対象のアプリへ移動でき、お知らせを参照できる。通知配信や複数ポータルはこの契約に含まない。
