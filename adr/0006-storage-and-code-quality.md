# 記録の分離とコード品質の検査

## 判断と根拠

INT-006に基づく保守作業として、[ADR-005](0005-local-runtime-and-tests.md)のJSON集約保存の部分を置き換える。ローカルD1、共通Repository、DB非依存の通常検証、ローカル利用限定の判断は維持する。

従来はアプリの定義・全記録・システム項目を一つのJSON列に保存していた。記録の所属や番号をDBが検査できず、一件の編集でも集約全体を書き直していた。

`applications`にはID、リビジョン、次の番号、下書き、反映済み定義とCAS操作識別子を置く。`records`には所属アプリ、記録ID、番号、作成／更新日時・実行者、入力値を置く。複合主キー、所属アプリへの外部キー、アプリ内番号のUNIQUE制約、正の整数・JSONオブジェクトのCHECK制約を使う。番号のUNIQUE索引はアプリ別・番号順の読み出しにも使い、同じ列の索引を重複して作らない。

可変の定義と入力値はJSONを維持する。項目の追加ごとにDDLを実行する方式や全値のEAV化は、現在の取得・更新の要件に対して複雑になるため採用しない。項目型・反映の適合性は共通の契約／ドメインで検証する。フィールド値の検索索引は検索要件が未決のため追加しない。

D1のbatchトランザクション内でアプリのCAS、削除対象の除去、記録のUPSERTを実行する。書き込みごとの一意なtokenにより、CASが失敗した場合は後続の記録操作を無効にする。UPSERTは値が変わった場合だけUPDATEし、未変更の記録を書き直さない。読み出しは単一のJOINで同一スナップショットを取得する。

既存のRepository/APIは集約を受け渡すため、全記録の読み出しと候補JSONの転送・照合は残る。大量データ向けの最適化完了やページング対応を意味しない。取得契約の分割は将来の検索・一覧要件に合わせて判断する。

追加の0002マイグレーションで旧データをコピーし、アプリの並び、下書き／反映済み定義、記録、採番を維持する。既存の0001は変更しない。制約に適合しないデータは移行を失敗させ、黙って削除・補正しない。利用者のDBへ自動適用はしない。

## lintとformat

Biomeを版固定で導入し、推奨lint、import整理、formatterを使う。EditorConfigの空白2文字・LF・末尾改行と合わせ、行幅は100文字を目安とする。通常のcheckと公開CIで警告も失敗扱いとする。Git除外に加えて非公開資料と生成物を明示的に除外する。SQLとMarkdownの整形はBiomeの対象外で、文書検査とdiff検査は従来どおり使う。

既存の横スクロール領域、上下ボタンを代替に持つドラッグ操作、リビジョン変更時の入力リセット、状態を持たないエラー文一覧、動きを減らす設定には理由付きの局所lint注記を置く。推奨ルール全体を無効化せず、既存の操作・アクセシビリティを維持する。

typescript-eslintは確認時点のpeerDependenciesがTypeScript 6.1未満で、既存のTypeScript 7に対応しない。コンパイラーの変更やpeer依存の強制無視を避け、TypeScriptコンパイラーに依存しないBiomeを選んだ。型検査は引き続きtscが担う。
