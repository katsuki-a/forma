# 文字列リソース

製品が用意する文言は `ja.ts`、型付きの参照・補間・エラー表示は `index.ts` に置く。現在提供する言語は日本語のみ。文体の基準は[デザインシステム](../../design/README.md)、振る舞いは[FRM-022/023](../../spec/0003-design-system.md)を参照する。

## 文言を追加する

1. 用途で `editor.fieldName` のようなキーを付ける。文言変更時もキーを維持する。異なる文脈の語が同じ日本語でも、将来別の訳になり得るならキーを分ける。
2. 一つの文を一つの値にする。固定のラベルを差し込んで文を組み立てず、必要なら文全体を分ける。差し込み値は `{{label}}`、`{{count}}` のように名前を付け、実行時に決まる利用者の入力・件数に使う。
3. `t("editor.fieldName", { position: index + 1 })` で参照する。キーと必須値を型検査する。件数は数値の `count` で渡す。動的キーは列挙型から導く。
4. APIエラーと入力検証のIssueには `describe` で `messageKey` と `messageParams` を付ける。既存の `code` は判定用として維持する。計算エラーの項目名・記録番号は文に埋め込まず別の属性で運び、表示時に翻訳する。`message` は既定言語の互換表示として返す。
5. `npm run check:local` を実行する。日本語の直書きはESLintが検出する。英語など日本語文字を含まない直書きや自然さはレビューで確認する。

Zodの独自メッセージはキーとして設定し、`describeValidation` で表示へ変換する。Zodの英語文言をキーにしたり、そのままUIへ表示したりしない。HTMLとして翻訳文を挿入しない。補間時のHTMLエスケープはReactのテキスト描画が担う。React以外でHTMLに挿入する場合は別途その出力先に応じたエスケープが必要。

## 翻訳を追加する場合

提供言語と切替UIは未決。`createTranslator` は言語ごとに独立したインスタンスを作り、欠けた翻訳は日本語へ戻す。キーや差し込み値が不正なカタログは拒否する。数に応じた表現はi18nextの `_one` / `_other` などを使い、元のキーと `count` を維持する。検証用の英語カタログは製品の提供言語ではない。

追加時は静的な初期テンプレート・候補名・型名を作成時の言語で評価すること、Reactへの言語状態の接続、HTMLのlangとtitle、日時の表示形式を合わせて確認する。現在のテンプレートは日本語で作成される。既に保存された定義や記録の内容は言語変更で書き換えない。日時は引き続きAPIのISO形式を表示し、表示用のタイムゾーン選択は今回追加していない。
